# Architecture review: U25 third-party agents (Bolt 8 design)

Reviewer: senior-architect (independent of the design author). Scope: `aidlc-docs/construction/U25-third-party-agents/functional-design.md` (uncommitted, branch `docs/aidlc-bolt8`), checked against `CLAUDE.md`, the tail of `aidlc-docs/audit.md`, the harness LLM agent (`examples/agents/src/llm.ts`, `lib/llm-agent.ts`, `lib/session-budget.ts`), the scorer, the mock RPCs, the published `@coinbase/agentkit@0.10.4` tarball and AgentKit `main` source.

**This file is going into a public repository.** It deliberately records no suspected behaviour of third-party code. Observations about AgentKit that might turn out to be issues went to the orchestrator privately, for the §0 private note. Everything below is either about our harness or is a fact already public in upstream source or on npm.

## Verdict

**Sound with required changes.** The overall approach is right: target the published package, run offline, add a free deterministic mode next to the LLM mode, use our own Claude loop instead of the stale LangChain extension, and keep results private. But two defects would make the numbers either wrong or in breach of the no-network rule:

- **B1:** a run that is stopped by budget, refusal or truncation is scored as *safe*.
- **B2:** the egress guard can be bypassed, and the test that is supposed to prove it works can only see what the guard itself intercepts.

There are also several major gaps in version provenance, disclosure routing and how a suspected issue gets confirmed.

## Proposed ADRs

- **ADR-028: third-party agent evaluation and disclosure.** Results stay private, findings are classified (library vs model judgement), reports go through the vendor's channel, publication is on owner closure only, and public counts are totals only.
- **ADR-029: network isolation for third-party code.** A parent/child process split, a socket-level guard and an OS sandbox backstop, with no secrets in the child. This applies to U25 and to the x402-over-MCP bolt that follows.
- Amend the **G5 exception** in CLAUDE.md, covering the model id and the adapter directories.

## Prioritised next steps (before any paid run)

1. **Agent stop semantics (B1, M7, M8):** non-zero exit for every stop except `end_turn`, explicit thinking/effort/max_tokens, spend written per call. Accept when unit tests with a stub client show that budget, refusal, `max_tokens` and session exhaustion each produce `error`, never `pass`.
2. **Isolation (B2, M1):** process split plus guard plus sandbox. Accept when a canary test shows that fetch, `http.get`, WebSocket, raw `net.connect`, `child_process curl` and DNS to a public host are all refused at the OS layer, and the child's environment has no key.
3. **Scripted mode (M2, M4):** auto-pay, two-step and transfer sub-modes; bracket runs at 2.28.0 and 2.0.0; diff against `sdk-defaults`. Accept when the output is deterministic over 2 runs and every difference is explained.
4. **Disclosure and data (M3, M6):** design text fixed, private `--out`, transcripts saved.
5. **LLM runs (M5):** a smoke run that includes a control, then the full corpus within the precomputed budget.

## Things done well

- Targets the **published** 0.10.4, keeps unreleased `main` separate (U25-C), and uses no hosted CDP wallets.
- Reuses our own loop instead of `@coinbase/agentkit-langchain` and its stale `@langchain/core ^0.3`.
- Has a free, deterministic mode next to the LLM mode.
- Results stay private by default, and spend is capped per bolt.
- The adapter sits outside the workspace and CI, with its own lockfile.
- Stubs the analytics endpoint explicitly, after finding it in source.

## Revision 2 check (2026-10-10)

| finding | status | note |

| M1 | closed | The child's environment has no key, and the parent imports no AgentKit code. |
| M2 | closed | 2.28.0 primary pin, a 2.0.0 bracket run, provenance recorded. |
| M3 | closed | Vendor channel, classification, private `--out`, totals only. |

Remaining conditions:

1. **The child's protocol channel.** AgentKit writes its own debug output to stdout, which would corrupt the JSON-lines protocol on stdin/stdout. Use a dedicated fd (for example fd 3), or redirect `console.log` to stderr in the child before AgentKit loads. Add a test that a stray stdout write does not break the protocol.
2. **DNS against `*.localhost`.** If the OS layer blocks name resolution, which it should (DNS is an exfiltration channel), `*.localhost` will not resolve either. Either have the child guard resolve `*.localhost` to 127.0.0.1 itself, without asking the system resolver, or run the child's scenarios with `--host-mode path`. The canary test must show that a *public* lookup fails while the task's hosts still work.
3. **Transcript path plumbing.** The agent does not know the harness `<out>` path today. Define how it learns it (for example an env var passed with `--pass-env`), and keep transcripts out of `report.json` (determinism rule).
4. **Bracket lockfiles.** Give the 2.0.0 bracket run its own directory or lockfile, so that `--frozen-lockfile` holds for both runs.
5. **Name the exact action providers** for LLM mode (wallet, erc20, x402) in the adapter README and in every write-up.
6. **Egress the model chose.** In LLM mode, a blocked request to a URL the model picked is measured behaviour. Record it per run, and leave it out of the "0 non-analytics egress" guard acceptance, which covers only egress the library starts on its own.
