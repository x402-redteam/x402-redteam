## 1. GitHub Action (`action.yml` at the repo root, composite)
The root location lets people reference it as `uses: <owner>/x402-redteam@v0`.

Inputs:
| input | default | notes |
|---|---|---|
| `agent` | required | the agent command |
| `chains` | `evm,svm` | |
| `corpus` | bundled `corpus/` | |
| `repeat` | `1` | |
| `timeout` | `60` | |
| `fail-on` | `high` | |
| `agent-id` | `${{ github.repository }}` | |
| `guardrail-id` | `unknown` | |
| `upload-sarif` | `true` | |
| `out` | `x402-redteam-out` | |

Steps:
1. `actions/setup-node@v4` (Node 20) and corepack pnpm.
2. `pnpm install --frozen-lockfile` in `${{ github.action_path }}`.
3. Run `pnpm -C ${{ github.action_path }} exec x402-redteam run …` with the working directory set to `${{ github.workspace }}`, so the agent command resolves in the user's repo. Capture the exit code and don't fail yet.
4. `github/codeql-action/upload-sarif@v3`, if `upload-sarif` is set, with `category: x402-redteam`.
5. `actions/upload-artifact@v4` with the out dir.
6. Append `report.md` to `$GITHUB_STEP_SUMMARY`.
7. Exit with the saved code.

Outputs: `report-json` (path), `pass-rate`, `unauthorized-usd`.

Add `.github/workflows/self-test.yml`, which runs the action from the local checkout against both reference agents:
- `examples/agents` naive must fail. Assert the exit code is 1 with `continue-on-error` plus a check step.
- guarded must pass.

Lint the action and workflows with `actionlint` if it's installed; otherwise note it in the report.

## 3. Leaderboard
- `results/<guardrail-id>.json` holds committed report.json files. Seed it with `naive-baseline.json` and `guarded-reference.json`, generated by actually running the CLI.
- `packages/leaderboard` (or `scripts/leaderboard.ts`; prefer the script for the MVP) reads `results/*.json` and writes `LEADERBOARD.md` with these columns:
  - rank
  - guardrail
  - scenarios passed / total
  - pass rate
  - unauthorized $ at risk
  - worst category
  - corpus_hash (short)
  - harness version
- Rank by scenarios passed descending, then unauthorized $ ascending.
- Only results whose `corpus_hash` equals the current corpus hash are ranked. Stale ones are listed separately as "stale corpus".
- `pnpm leaderboard` regenerates the file. A test covers ranking, the stale split and deterministic output.
- `CONTRIBUTING.md` explains how to submit a guardrail result by PR (run the CLI, commit `results/<id>.json`, CI re-verifies the corpus_hash) and how to add a scenario.
