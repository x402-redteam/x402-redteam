# U24-B — Node 24 runtime and locale-independent canonical ordering · Functional Design

Author: senior-architect · Implementer: one Sonnet developer · Bolt 7 **Phase 0a** (runs first and alone; it touches files C, D and F take over afterwards)
Contract: ADR-020, ADR-019 §3, review findings M5, L7 and L11. Size: about half a day.

## 1. Goal
1. The project runs on a supported LTS: Node 24 is primary and Node 22.14 is the floor.
2. Every hash and every sorted output in `report.json`, `corpus_hash` and `LEADERBOARD.md` is independent of locale and ICU version. This is a precondition for the Node matrix in U24-C and for reproducing ranked runs across machines.

## 3. Behaviour rules
- Ordering is by code unit. For ASCII ids, which are all the current scenario ids, categories and keys, this equals `localeCompare` **except** around case and punctuation (`_`, `-`, `.`, upper case).
- Do not try to preserve the old order. Instead:
  - run `pnpm leaderboard` and regenerate the 4 reference results (orchestrator, see §5);
  - if `report.json` bytes change, record the reason in the unit report: "ordering moved from ICU collation to code-unit order".
- The `corpus_hash` algorithm is unchanged except for the comparator. If the hash changes, the corpus version note must say so (U24-E release notes).

## 4. Acceptance (developer; each < 3 min)
- `pnpm install --frozen-lockfile` after the lockfile change; `pnpm lint && pnpm typecheck && pnpm test` green on local Node 20.19. That's still fine locally: `engines` isn't enforced and CLAUDE.md allows it.
- If `nvm`/`fnm` is **already** present, also run `pnpm test` on Node 24. Don't install a version manager (CLAUDE.md: no global installs). Otherwise leave this to CI.
- `canonical.test.ts`:
  - key order is identical under `LANG=tr_TR.UTF-8`, `sv_SE` and `C`, by spawning `node -e` with each env;
  - `["a_b","a-b","A","a","é"]` sorts to the documented code-unit order;
  - nested objects; arrays not reordered.
- `grep -rn "localeCompare" packages/*/src` → zero hits. This becomes a unit test that reads the source tree.
- `action-yaml.test.ts` and `ranked-workflows.test.ts` still pass, or are updated only for the node version string.

## 5. Orchestrator-only
- Resolve the `node:24-bookworm-slim` digest through the registry API, without docker: `https://registry-1.docker.io/v2/library/node/manifests/24-bookworm-slim` with an anonymous token, or `crane digest` if available. Record it in audit.md and hand it to the developer.
- Run the four reference suites and `pnpm leaderboard`. Commit regenerated `results/*.json` and `LEADERBOARD.md` if the bytes changed. Run full `pnpm test:e2e` once on a quiet machine.

## 6. Do not
- Change the report schema or add fields (recording `node_version` in the config fingerprint would be a contract change → separate ADR).
- Touch any other workflow line (pins belong to U24-D; triggers and jobs belong to U24-C).
- Bump other dependencies.
